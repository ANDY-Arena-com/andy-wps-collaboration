01 / Project

One board, two strategic systems

Chess pieces occupy squares. Go stones occupy intersections, including within the overlapping chess area. The models must navigate both layers and act under defined resource budgets.

ArenaWatch actual model competitions.
LabInspect decisions, errors, time and tokens.
DocumentationMake rules, methods and uncertainty transparent.

Match outcomes are distinct from model qualification decisions. The numerical Strategy component and aggregate ANDY Score are not yet independently validated.

02 / Website × Theater

A real match, presented in fast-forward

The website's Theater Replay V0.7.2 (integration test) presents a recorded OpenAI Astra vs Google Gemini 4 Argon match. White wins by chess checkmate. The recorded duration is roughly two hours and nineteen minutes; the theater presents the events more quickly.

The Fight Card, optional guided tour, countdown, commentary, event alerts and victory ceremony are presentation layers. The recorded moves, failures and result must remain unchanged. The original JSONL stays separate from derived replay data.

The replay is built with HTML, CSS and JavaScript and does not require active LLM calls. The website and theater can run independently of the Python game engine.

The current integration test does not yet constitute an independently engine-validated public archive or a fully released online game.
03 / Design & perception

What is visible is not always perceived

ANDY's Designer adjusts board, pieces, Go stones, contrast, typography and UI density without changing game state. The design needs to remain legible at the beginning, middle and end of a match. This is a research question about human perception—not yet a measured effect of the ANDY interface.

04 / Open records

One match. One original. Verifiable provenance.

Engine events → Original JSONL → SHA-256 → Replay / Lab

Featured match ID: andy_0c0f7413fdf6. The original file name is andy_0c0f7413fdf6.jsonl. The SHA-256 of the original 494,454-byte JSONL file supplied in the V0.7.2 package is:

7f955acabc196c592c8b6a623fd9b644d9110e35f482c14fd6704a32682f093e

That checksum was independently recalculated from the supplied package bytes and matches the hash embedded in the derived Theater JSON. It establishes a byte-level reference only. A hash alone does not prove authorship, trustworthy publication, correct chess/Go rules or faithfully derived positions.

Our proposed archive structure will add per-artifact hashes, the engine/rules version, reconstruction reports, a public machine-readable manifest and, eventually, independently verifiable signatures. These are planned safeguards, not features already implemented.

05 / Provider identification

Brand identity is not endorsement

A provider logo identifies a company; the competitive actor is a particular model with a particular configuration and match record. Provider logos in the current Theater are experimental identifiers, not a claim of partnership, sponsorship or an official provider benchmark.

Before public production use, official brand guidelines, asset permissions, placement and attribution must be reviewed. Keep text-only provider names and neutral badges as alternatives. Do not recolor or alter protected logos, use them as ANDY branding or imply affiliation.

Official policies: OpenAI brand guidelines · Google Brand Resource Center.
